# Weather Desk

Vue.js 수업에서 진행한 날씨 과제를 바탕으로 만든 최종 프로젝트입니다.

처음에는 한 파일 안에 날씨 목록을 출력하는 것부터 시작했고, 이후 Composition API, 컴포넌트, Router, Pinia, Axios를 차례로 적용했습니다. 마지막에는 실제 날씨와 환경 데이터를 불러오고 Element Plus로 화면을 정리했습니다.

## 프로젝트 링크

- 배포 주소: https://skala-practice-ten.vercel.app

## 과제 진행 과정

### 1. 날씨 Mockup

처음에는 서울, 수원, 부산의 임시 날씨 데이터를 배열로 만들었습니다.

- `v-for`로 도시별 날씨 카드 반복 출력
- `v-if`로 온도에 따라 더움과 선선함 표시
- `v-model`로 도시 검색어 입력
- 카드 선택과 상세보기 버튼 이벤트 처리

이 단계에서는 Vue가 데이터를 기준으로 HTML을 자동으로 바꿔준다는 점을 익혔습니다.

### 2. Composition API 적용

한 파일 안에 있던 데이터를 반응형 상태로 관리했습니다.

- `ref`로 검색어, 선택된 도시, 필터 상태 관리
- `computed`로 검색 결과와 더운 도시 목록 계산
- `watch`, `watchEffect`로 상태 변화 확인

처음에는 `ref`와 `computed`의 차이가 헷갈렸지만, 직접 바뀌는 값은 `ref`, 다른 값을 이용해 계산하는 값은 `computed`로 구분하면서 이해할 수 있었습니다.

### 3. 컴포넌트 분리

한 파일에 모여 있던 화면을 역할에 따라 나눴습니다.

- `SearchBar.vue`: 도시 검색
- `TemperatureFilter.vue`: 더운 도시 필터
- `WeatherCard.vue`: 도시별 날씨 표시
- `BaseDashboardCard.vue`: 공통 카드 영역

부모에서 자식으로 데이터를 보낼 때는 Props를 사용하고, 자식에서 발생한 일을 부모에게 알릴 때는 Emits를 사용했습니다. 컴포넌트를 나누니 처음에는 파일이 많아져 복잡해 보였지만, 각 파일의 역할은 더 분명해졌습니다.

### 4. Vue Router 적용

화면마다 URL을 만들고 새로고침 없이 이동하도록 구성했습니다.

- `/weather`: 날씨 대시보드
- `/weather/guide`: 날씨 가이드
- `/weather/about`: 서비스 소개
- `/weather/:cityId`: 도시별 상세 날씨
- 잘못된 주소에 대한 404 페이지

특히 상세보기 버튼을 누르면 도시 ID가 포함된 주소로 이동하고, 상세 페이지에서 해당 ID에 맞는 도시 데이터를 찾도록 구현했습니다.

### 5. Pinia Store 적용

여러 화면에서 같이 사용하는 설정을 Pinia Store로 분리했습니다.

- 섭씨와 화씨 단위 전환
- 더움 기준 온도 조절
- 대시보드와 상세 화면에 동일한 설정 적용

Store를 사용하기 전에는 같은 값을 여러 컴포넌트에 계속 전달해야 했지만, Pinia를 적용한 뒤에는 필요한 화면에서 같은 설정을 바로 가져올 수 있었습니다.

### 6. 실제 API와 UI 적용

임시 날씨 데이터를 실제 API 응답으로 교체했습니다.

- Axios를 이용한 비동기 통신
- OpenWeather 현재 날씨 조회
- 시간대별 예보와 5일 예보 조회
- Open-Meteo 공기질, 미세먼지, 초미세먼지, 자외선 조회
- 로딩, 오류, 빈 검색 결과와 다시 시도 화면 처리
- Element Plus를 이용한 입력창, 카드, 탭, 알림 UI 구성

API 요청 중에는 로딩 화면을 보여주고, 요청에 실패하면 오류 메시지와 다시 시도 버튼이 나오도록 했습니다. API 키는 코드에 직접 작성하지 않고 `.env.local`에서 관리했습니다.

## 서비스 이용 흐름

### 1. 대시보드에서 현재 날씨 확인

서비스에 들어오면 서울, 수원, 부산의 현재 날씨를 먼저 불러옵니다. 각 카드에서 현재 기온과 날씨 상태를 확인할 수 있으며, OpenWeather의 날씨 코드를 `맑음`, `구름 많음`, `약한 비`처럼 이해하기 쉬운 이름과 이모지로 바꿔 표시합니다.

데이터를 불러오는 동안에는 로딩 화면이 나오고, 요청에 실패하면 오류 내용과 다시 시도 버튼이 표시됩니다.

### 2. 원하는 도시만 검색하고 조건 설정

도시 검색창에 한글을 입력하면 입력 내용이 바로 검색 결과에 반영됩니다. `더운 도시만 보기`를 켜면 현재 설정한 기준 온도 이상의 도시만 남습니다.

상단 설정에서는 섭씨와 화씨를 전환하거나 더움 기준을 직접 높이고 낮출 수 있습니다. 이 설정은 Pinia Store에서 관리하기 때문에 대시보드와 상세 페이지가 같은 단위와 기준을 사용합니다.

### 3. 도시를 선택해 상세 예보 확인

날씨 카드의 상세보기 버튼을 누르면 `/weather/:cityId` 형식의 도시별 주소로 이동합니다. 상세 화면에서는 현재 기온, 습도, 풍속뿐 아니라 앞으로 24시간의 기온과 강수확률, 약 5일간의 대표 예보를 확인할 수 있습니다.

주소에 포함된 도시 ID를 이용해 어떤 도시의 데이터를 불러올지 결정하기 때문에 상세 주소를 직접 열어도 같은 도시 정보가 표시됩니다.

### 4. 날씨 가이드에서 생활 환경 확인

날씨 가이드에서는 서울, 수원, 부산 중 한 도시를 선택할 수 있습니다. 선택한 도시의 AQI, 미세먼지, 초미세먼지와 자외선 지수를 Open-Meteo API에서 다시 불러옵니다.

가져온 수치는 `computed`로 분석합니다. 공기질이나 자외선이 높으면 야외 활동, 마스크, 자외선 차단과 관련된 행동요령이 현재 상태에 맞게 달라집니다.

### 5. 서비스 소개에서 개발 과정 확인

서비스 소개 화면은 한 페이지에 모든 내용을 나열하지 않고 탭으로 구분했습니다. 현재 기능, 과제별 개발 과정과 데이터가 API에서 화면까지 전달되는 구조를 필요한 부분만 선택해서 볼 수 있습니다.

모든 화면은 Vue Router로 연결했으며 잘못된 주소에 접근하면 404 안내 화면을 보여줍니다. Element Plus를 사용해 로딩, 오류, 빈 결과 상태를 일관되게 표현하고 모바일 화면에서도 사용할 수 있도록 구성했습니다.

## 로컬 실행 방법

프로젝트 폴더로 이동합니다.

```bash
cd vue.js/weather-final
```

필요한 패키지를 설치합니다.

```bash
npm install
```

`.env.example`을 참고해 프로젝트 최상위에 `.env.local` 파일을 만들고 OpenWeather API 키를 입력합니다.

```env
VITE_OPENWEATHER_API_KEY=발급받은_API_KEY
```

개발 서버를 실행합니다.

```bash
npm run dev
```

배포용 파일이 정상적으로 만들어지는지 확인할 때는 다음 명령을 사용합니다.

```bash
npm run build
```

`build`는 Vue 소스 코드를 배포에 사용할 HTML, CSS, JavaScript 파일로 변환해 `dist` 폴더를 만드는 과정입니다. `deploy`는 이 빌드 결과를 Vercel 서버에 올려 다른 사람이 접속할 수 있는 주소로 공개하는 과정입니다.

## Vercel 배포 설정

이 프로젝트는 Vercel에서 다음 값으로 정적 배포합니다.

```text
Root Directory: vue.js/weather-final
Framework Preset: Vite
Build Command: npm run build
Output Directory: dist
```

Vercel의 Environment Variables에는 다음 값을 등록해야 합니다.

```text
VITE_OPENWEATHER_API_KEY=발급받은_API_KEY
```

Vue Router의 상세 주소에서 새로고침해도 404가 발생하지 않도록 `vercel.json`에서 모든 요청을 `index.html`로 연결했습니다. 배포를 완료하면 위의 프로젝트 링크에 실제 Vercel 주소를 추가합니다.

## 느낀 점

처음에는 `App.vue` 한 파일에 코드를 추가하는 방식이 더 간단해 보였습니다. 하지만 기능이 늘어나면서 검색, 카드, 라우팅, 설정과 API 요청을 각각 분리해야 코드를 찾고 수정하기 쉽다는 것을 알게 되었습니다.

또한 화면에 데이터를 출력하는 것뿐 아니라 로딩 중인 경우, 요청에 실패한 경우, 검색 결과가 없는 경우도 함께 처리해야 하나의 서비스처럼 사용할 수 있다는 점을 배웠습니다.

이번 과제를 통해 Vue의 문법을 따로 외우는 것보다 `데이터가 어디에서 만들어지고, 어떤 컴포넌트로 전달되며, 화면이 어떻게 바뀌는지` 흐름을 이해하는 것이 중요하다는 것을 느꼈습니다.
